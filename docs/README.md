# Design Record

The documents in this directory are Lucky Lode's design record: what
was decided, when, and why. They are kept as a living history — dated
decisions and their rationale stay visible — which is unusual for a
cryptocurrency project and intentional. Current-state summaries live
in [`00-lucky-lode-at-a-glance.md`](00-lucky-lode-at-a-glance.md);
everything else is the reasoning behind it.

| Doc | Subject |
|---|---|
| [`00`](00-lucky-lode-at-a-glance.md) | The coin at a glance: supply, consensus, the game layer, status |
| [`01`](01-thesis-and-positioning.md) | Why this niche is open, who it's for, what killed the predecessors |
| [`02`](02-technical-stack.md) | Fork-Verus decision, algorithm strategy, the modular stack |
| [`03`](03-fun-and-retention.md) | The excitement layer: jackpot blocks, leagues, streaks, seasons, badges — the core differentiator |
| [`04`](04-economics-launch-roadmap.md) | Emission, dev funding without breaking fair-launch trust, launch sequence, roadmap, risks |
| [`05`](05-pow-algorithm.md) | **LuckyHash v1** — the PoW spec, frozen with test vectors, difficulty rules, and mainnet gates |
| [`06`](06-jackpot-lottery.md) | Jackpot blocks, the Lucky Pot, draw rules, funding conservation |
| [`07`](07-android-miner.md) | Android app and the frozen thermal/power scheduler policy |
| [`09`](09-gpu-posture.md) | GPU policy: the 10x tripwire, tuning levers, measurement cadence |
| [`11`](11-transactions-and-staking.md) | Transaction posture, why classic masternodes are redundant, PoS extensions |
| [`12`](12-network-as-game.md) | The network as a game: mechanic catalog, funding conservation, legal gates, the luck table |
| [`13`](13-naming-and-brand-record.md) | Naming and brand record: every decision with dates, frozen consensus strings, ports and datadirs |

historical.
